# AGENTS.md — LLM Wiki Schema (xiuliuhe)

This repository is configured as an **LLM-maintained wiki** following the Karpathy "LLM Wiki" pattern (same as the `xwcz` / `amtb` repos). This file is the schema: it tells the LLM how the wiki is structured, what conventions to follow, and what workflows to run. Read this file first at the start of every session before touching the wiki.

## Purpose

Build a persistent, interlinked, compounding knowledge base of the teachings published by **修六和 / 慈云法语 / m.xiuliuhe.org**（刘素云老师主讲，净土与修六和教育）. The wiki sits between the reader and the raw corpus. The LLM writes and maintains the wiki; the human curates which albums to ingest and asks questions.

The raw corpus is **cloned from m.xiuliuhe.org** through its public REST API (`https://m.xiuliuhe.org/api/`). Nothing is hand-copied; everything under `doc/` is produced by the sync tools.

## Repository layout

```
xiuliuhe/
  AGENTS.md             <- this file (schema)
  catalog.json          <- generated by wiki/tools/fetch_catalog.py (category→album→episode tree)
  doc/                  <- RAW SOURCES (updated only via sync tools, never hand-edited)
    影音/
      <类别>/
        <相簿>/
          <NUM>.md      <- one transcript per episode
  wiki/                 <- THE WIKI (LLM-owned markdown)
    SCHEMA.md           <- page templates & examples
    README.md           <- home/overview
    index.md            <- content catalog
    log.md              <- chronological activity log
    raw-manifest.md     <- generated catalog of all raw albums (gen_manifest.py)
    tools/              <- sync pipeline (Python)
      api_client.py     <- API client + URL builders (getTextUrl, getAudioMp3Url, …)
      fetch_catalog.py  <- walk API → catalog.json
      download.py       <- fetch transcripts → doc/影音/…
      gen_manifest.py   <- regenerate raw-manifest.md
      requirements.txt
```

## The three layers

1. **Raw sources** — `doc/影音/`. Curated (by human choosing albums), git-tracked. The LLM reads from here and **writes only via the sync tools** (`python wiki/tools/fetch_catalog.py`, `download.py`, `gen_manifest.py`). Never hand-edit anything under `doc/`.
2. **The wiki** — `wiki/`. LLM-owned markdown. Create/update pages on ingest, query, and lint.
3. **The schema** — this file + `wiki/SCHEMA.md`. Co-evolve with the human.

## How resources are cloned (the model)

The xiuliuhe API is walked by `wiki/tools/fetch_catalog.py` → `catalog.json`:

- **Categories** (`category/list`) — 2 top-level (无量寿经, 专题讲演). Currently flat; code tolerates subcategories if `category/list?cid=<id>` ever returns children.
- **Albums** (`album/list?cid=<id>&page=<n>`) — the "series" unit (33+ albums). An album = one teaching title, e.g. `《無量壽經》複講第三回`, `智海拾零`. Fields: `id`, `title`, `total`, `album_num` (e.g. `PC-034`), `cover`, `author`.
- **Episodes** (`video/list?aid=<albumId>`) — one episode = one 集. Each episode carries:
  - `id` (episode id, for `video/detail`)
  - `num` (code, e.g. `PC-034-0001`, `56-154-0001`) — folder/page key and media URL key
  - `video` / `audio` codes (often same as `num`), `author`, `lecture_time` (date or timestamp), `title`
- **Transcript** (`video/detail?id=<episodeId>` and `article/detail?id=<episodeId>`) — the full teaching text as HTML; converted to markdown by `download.py`. The primary source is `video/detail`; `article/detail` is equivalent for xiuliuhe.

First two segments of `num` = series prefix (e.g. `PC-034`, `56-154`), used for the reference-link URLs.

Media URL builders live in `wiki/tools/api_client.py` (`get_video_mp4_url`, `get_audio_mp3_url`, `get_video_hls_url`, `get_poster_url`) — never hand-build URLs. Hosts are `https://s.liuhejing.cc/` (primary) and `https://d.liuhejing.cc/` (backup).

## Raw source format

- `doc/影音/<类别>/<相簿>/<NUM>.md` — one markdown file per episode, named by its code (`NUM`, e.g. `PC-034-0001.md`).
- The album folder name is the album **title** (Chinese); the series code is embedded in each page's first line.
- Every page's **first line** is metadata:
  `题目　　（共N集｜第N集）　　日期　　档名：NUM`
  Example: `智海拾零　　（共12集｜第1集）　　2026-03-28　　档名：PC-046-0001`
- Some episodes have **no transcript** (stub page with metadata only, body `<p>暂无</p>`) — still write the stub.
- See `wiki/raw-manifest.md` for the full album catalog (regenerate with `python wiki/tools/gen_manifest.py`).

## Wiki structure

One folder per top category. Inside each category folder: a category page and **one source page per album** (named by album Chinese title). Concept pages live in `wiki/概念/`.

```
wiki/
  无量寿经.md              <- category page
  无量寿经/
    《無量壽經》複講第三回.md  <- source page (one per album/series)
  专题讲演.md
  专题讲演/
    智海拾零.md
    极乐归舟.md
  ...
  概念/
    念佛.md
    因果.md
    ...
  问答/
    ...                  <- filed query answers
```

**Language**: all wiki page content is Simplified Chinese (with Traditional variants tolerated for titles like  《無量壽經》). Frontmatter tags/values may be Chinese or English. Never auto-translate sources; quote sparingly.

## Page types

### Category page (`无量寿经.md`)
- YAML frontmatter: `type: category`, `tags`, `updated`, `albums` (count).
- Lists its album/source pages with one-line descriptions, plus a short synthesis of what the category covers.

### Topic/subcategory page (`修六和.md`) — optional
- `type: topic`, `category`.
- Only if xiuliuhe adds subcategories later. Lists its albums with links.

### Source page (`智海拾零.md`)
- `type: source`, `category`, `topic`, `code`, `title`, `date`, `place` (if known), `pages`, `raw`, `media`.
- Sections: 概要 (summary), 重点 (key teachings), 相关概念 (wikilinks to concepts), 相关页面 (links to related albums/topics), 原始资料与影音 (GitHub links to raw folder + a per-episode table of text/media links).
- One page per album; cite the raw path so the reader can drill in.

### Concept page (`概念/念佛.md`)
- `type: concept`.
- Cross-cutting concepts that recur across many albums (念佛、因果、孝亲尊师、六和、菩提心、阿弥陀佛…). Evolving entity page: definition, how different sources present it, key quotes with citation, related concepts.
- Create a concept page when a term is central and recurs; do not create pages for one-off mentions.

### Answer pages (filed queries)
- `type: answer`. Created when a good Q&A result deserves persistence (comparisons, syntheses). Lives under `wiki/问答/`.

## Conventions

- **Naming**: files use the natural Chinese name for albums/topics/concepts. Num-code is only used inside `doc/`. No spaces in filenames; if needed use `_`.
- **Links**: Obsidian-style wikilinks `[[智海拾零]]`, `[[概念/念佛]]`. For source pages, link the album title.
- **Frontmatter**: always YAML `---` block. Keys: `type`, `category`, `topic`, `code`, `title`, `date`, `place`, `pages`, `raw`, `media`, `tags`, `updated`. Use `date: YYYY-MM-DD`.
- **Citations**: when a claim comes from a specific album, cite it as `〔PC-034〕` (series prefix) or link `[[智海拾零]]`; when citing a single episode use `〔PC-046-0001〕`.
- **Reference links**: every source page carries a `## 原始资料与影音` section with the raw folder link and a per-episode table of text (`md` GitHub blob) and media links. Do not omit episodes.
- **Tool-managed raw**: never hand-edit anything under `doc/`; change it only through the sync tools (see Source update workflow).

## Workflows

### Source update (sync raw corpus from m.xiuliuhe.org)
Run when the human asks to sync new/updated teachings, or at session start if unsure whether `doc/` is current.

Run from the **xiuliuhe repo root**:

```
python wiki/tools/fetch_catalog.py   # walk categories→albums→episodes → catalog.json
python wiki/tools/download.py        # fetch missing transcripts into doc/影音/… (incremental)
python wiki/tools/gen_manifest.py    # regenerate wiki/raw-manifest.md
```

- `download.py` is **incremental** — rerunning only fetches episodes not already on disk. Full runs can take a few minutes; use `--only <prefix>` to target an album/series (e.g. `python wiki/tools/download.py --only PC-046`).
- Verify: `raw-manifest.md` counts update; spot-check a new `.md` first line; `git status` under `doc/` shows only expected new files.
- Report to the human what was added/updated; if new albums appeared, run the Ingest workflow on them next.

### Ingest (one album at a time, with human review)
1. Read `wiki/raw-manifest.md` and `wiki/index.md` to find the album and check what exists.
2. Read the source pages of the album (all `.md` in its folder; start with the first episode).
3. Write/update the **source page** in the wiki: 概要, 重点, metadata, raw path, and the `## 原始资料与影音` section (see SCHEMA.md for URL formats).
4. Update/create **concept pages** referenced by the teachings.
5. Update the **category page** (and topic page if useful) if the album adds structure.
6. Update **`index.md`** (add/refresh the entry).
7. Append an entry to **`log.md`**: `## [YYYY-MM-DD] ingest|<系列> 标题` plus a short note.
8. Report to the human what was done; ask which album to ingest next.

### Query
1. Read `wiki/index.md` first to find relevant pages, then drill into them.
2. Synthesize an answer citing sources (`〔PC-034〕`).
3. If the answer is durable (comparison, analysis, synthesis), file it as an answer page under `wiki/问答/` and update `index.md` + `log.md`.

### Lint (periodic health-check)
- Find contradictions, stale claims, orphan pages, missing concept pages, and data gaps fillable by web search or by syncing more albums.
- Fix what is fixable in the wiki; report findings; append a `lint` entry to `log.md`.

## index.md and log.md

- **index.md** — content catalog by category. Every page gets a line: link + one-line summary (+ optional tags). Updated on every ingest/query-filing.
- **log.md** — append-only timeline. Every entry starts with `## [YYYY-MM-DD] type|detail`. Types: `ingest`, `query`, `answer`, `lint`, `schema`. Parseable with `grep "^## \[" wiki/log.md`.

## Tools

- `python wiki/tools/fetch_catalog.py` — walks the xiuliuhe API and writes `catalog.json` (categories → albums → episodes). Run from repo root.
- `python wiki/tools/download.py` — fetches transcripts (`video/detail`) into `doc/影音/…` as markdown. Incremental; supports `--only <prefix>` and `--dry-run`.
- `python wiki/tools/gen_manifest.py` — regenerates `wiki/raw-manifest.md` from the raw corpus.
- URL builders & API client: `wiki/tools/api_client.py` (`get_audio_mp3_url`, `get_video_mp4_url`, `get_video_hls_url`, `get_poster_url`, `build_numbered_asset_url`, media hosts). Reuse these; never hard-code URLs.
- Dependencies: `pip install -r wiki/tools/requirements.txt` if `requests` is used (currently stdlib-only; no extra deps required).

## Rules of thumb

- Prefer updating existing pages over creating new ones; keep the wiki small and linked.
- When in doubt about emphasis, ask the human.
- Never invent metadata; if the raw line is missing a field, leave it blank rather than guess.
- Keep every page focused; split long pages when they exceed roughly 150 lines. Exception: the `## 原始资料与影音` per-episode reference table grows with episode count by design and is exempt from the line limit (full tables never truncated).
- The wiki complements the reproducible clone: the point is to extract durable insight from `doc/`, not to duplicate it.
